## Architecture assessment

The non-UI `InCallService`, API 34+ live Telecom endpoint requests, local Bluetooth identity,
classic HFP evidence and bounded policy fit the requested product. The existing Phone app stays
default and the app does not mutate media/navigation routing. Brand names do not drive policy.
Retain this architecture rather than adding a replacement dialer, hidden audio setters or an
accessibility automation loop.

This remains a classic-HFP, SIM-backed cellular-call beta. Endpoint requests are advisory to
Telecom; accepted requests and displayed endpoints do not prove physical speaker/microphone use.
Android 17 request notifications identify the endpoint, not the user/app origin. A configured
Android Auto competitor's startup request can be indistinguishable from a manual choice of that
same device. An already-submitted platform request cannot be recalled.

## Fixed in beta.18

| Source finding | Change and regression coverage |
| --- | --- |
| Endpoint objects survived the last call's removal | Clear endpoint/current snapshots between calls; require a new availability callback. Keep within-call request-generation resets separate. |
| Route now reused a generation and could overlap unfinished requests | Invalidate old callbacks for a new explicit transaction; refuse overlapping automatic/manual transactions. |
| Missing evidence at answer could restart a submitted dialing transaction | Preserve unfinished requests even after they move back to WAITING; test both projection and HFP evidence loss. |
| Other Bluetooth choices were less protected than speaker/handset/wired | Latch resolved third-device changes and protected API 37 request notifications. Ambiguous competitor startup activity remains observational. |
| Target among several reported HFP audio owners counted as confirmed | Multiple owners remain unknown; they cannot authorize selector recovery. |
| Paired-device/name reads ran on the setup UI thread | Independent single-slot worker, immutable choices, three-second timeout, permission recheck and screen-stop cancellation. Five production-query tests. |
| Process/power/exit diagnostics could block call-start callbacks | Separate zero-queue worker and bounded-age cache, with stall, saturation, failure and expiry tests. Missing evidence stays unavailable. |
| Mid-call unbind left an older successful result visible | Persist incomplete observation when a live call loses service observation. |
| Parked reports could span calls | UI and analyzer reject changed/absent completed-call identity. Legacy captures retain independent operator/evidence gates. |
| Retried publication could mix files from different builds | Verify local assets, stage a draft, download and verify the full APK/digest/report set, then publish. Published retries preserve and check existing assets. |
| Signed tags could mismatch versions, debug filters were incomplete, betas could appear stable | Exact source/tag validation, both debug tag exclusions, prerelease publication, full Python checks and portable digest filenames. |
| README described removed saved-name fallback and broad uninstall guidance | Correct identity/upgrade instructions; retain package and signing identity. |

All six initial new service regressions failed against the original production service source;

## Remaining external/platform gates

- Install/update the exact released APK; check retained settings and AppOp on a phone.
- Exercise incoming/outgoing calls, answer takeover, manual changes during startup, screen-off,
  sleep, reboot, app closed, disconnect/reconnect and repeated calls.
- Independently verify physical speaker and microphone, Android Auto navigation during calls,
  and media resumption. Compare exported timing and observation gaps with what happened.
- Validate real API 37 callbacks and Android 14–16 callback ordering. Qualify other phone/headset/car
  combinations; the prior Samsung/BMW proof of concept is not universal compatibility evidence.
- Installation-only authorization while preserving the Phone app needs supported privileged
  provisioning or platform integration. An ordinary APK cannot self-grant this protected access.
- LE Audio/hearing-aid identity and active-audio evidence, and broader VoIP visibility/eligibility,
  need separate supported designs and physical qualification. Current routing fails closed.
- A system Binder read may never return. Work remains bounded and evidence unavailable; Java
  interruption cannot force the system service to complete.
